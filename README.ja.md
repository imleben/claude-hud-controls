# claude-hud-controls
[English](README.md) · [한국어](README.ko.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md)

Claude Codeのプロンプトの下に、クリックで操作できるモデル、推論レベル、ワークフロー、ultracodeの切り替えを表示します。ステータスラインのHUDもその状態に連動し、推論レベルを選ぶと、両方にすぐ反映されます。

![上部がステータスライン、下部がコントロール行](docs/screenshot.png)

上部の行はステータスライン（`hud/`）です。モデルと推論レベル（`Opus 5.5
◔ med`）、プロジェクトとgitブランチに続き、コンテキスト、5時間枠、7日間枠の残量を表示し、使用量に応じて色が変わります。最下部はコントロール行（mod）で、Claude Codeのモード表示の横に並びます。この例ではOpusが動作しており、推論レベルの選択肢が開いて`md`が選択され、ワークフロー（`wf`）はオン、ultracode（`uc`）はオフになっています。

このリポジトリは、次の2つの部分で構成されています。

| 部分 | 内容 | インストール方法 |
| --- | --- | --- |
| `hud-controls`（リポジトリのルート） | プロンプトの下にコントロール行を表示するClaude Codeのmod | `/plugin install`（後述） |
| `hud/` | [claude-hud](https://github.com/jarrodwatts/claude-hud) 0.8.0を改変したステータスライン | クローン + `statusLine`の設定（後述） |

それぞれ単独でも動作します。併用すると、コントロール行でのクリックがステータスラインにすぐ反映され、Claude Codeが報告する推論レベルもコントロール行に表示されます。

## 機能

### コントロール行（`hud-controls`）

ターミナルとデスクトップアプリで、プロンプトの下にあるヒント行を置き換えます。Claude Code自身のヒント（`? for shortcuts`など）は、その上に残ります。コントロール行はボタンではなくプレーンテキストとして描画されるため、ポインターを重ねてもハイライトや反転表示は起きません。ウィンドウの幅が狭い場合は複数行に折り返され、折り返された行もクリックできます。

**モデル：`Fable Opus Sonnet Haiku`**

- モデルファミリーごとに色が異なり、Fableは紫、Opusはオレンジ、Sonnetは青、Haikuは緑です。動作中のモデルは鮮やかな色の太字で表示され、ほかのモデルは薄く表示されます。
- クリックするとモデルが切り替わり、ファミリーのエイリアス（`opus`、`sonnet`など）がモデル設定として保存されます。エイリアスは常にそのファミリーの最新リリースを指すため、コントロール行にはファミリー名だけを表示します。正確なバージョンはステータスラインに表示されます。
  - Claude Codeが設定を受け付けない場合は、代わりに`/model <alias>`を実行します。
- モデルをクリックすると、推論レベルの選択肢も開きます。選択肢が開いている状態で動作中のモデルをクリックすると、選択肢が閉じます。

**推論レベル：`lw md hg xh mx`**（低、中、高、非常に高い、最大）

- 選択肢は動作中のモデルの色で表示されます。現在有効なレベルは太字になります。
- クリックは、プロンプトに`/effort <level>`と入力した場合と同じように動作し、確認手順やモデルごとの制限も同じです。
- ターンの途中でも、選んだレベルはすぐに選択済みとして表示されます。
  - Claude Codeがプラグインの`/effort`を実行するのは現在のターンが終了してからなので、ターン中のクリックはそれまで待機します。その旨がトーストに表示されます（`Effort high: applies when the current turn ends`）。
  - 待機中は、コントロール行のレベルが太字と**下線**で表示され、ステータスラインにも選んだレベルが表示されます。
  - コマンドが実行されると、下線が消えます。
- 1つのターン中に複数のレベルをクリックした場合、最後に選んだレベルだけが実行されます。クリックするたびに、それまでの選択が置き換わります。
- プロンプトに入力した`/effort`も、待機中のクリックを置き換えます。
  - レベルまたは`auto`を指定すると、待機中のレベルが置き換わります。
  - `ultracode on|off`を指定すると、待機中の`uc`のクリックが置き換わります。
- コントロール行には、実際に適用された状態が表示されます。
  - Claude Codeがレベルを受け付けない場合は、理由がトーストに表示され（`Effort not changed: …`）、コントロール行は元のレベルを維持します。
  - Claude Codeの確認を拒否した場合は、Claude Codeが維持したレベルが表示されます。
  - モデルによってレベルが上限に制限された場合は、制限後のレベルが表示されます。
  - `/effort auto`の後はモデルがレベルを選ぶため、どのレベルにも選択表示は付きません。
- コントロール行は、複数の情報源から有効なレベルを取得します。
  - セッション開始時は、モデルごとの設定（`modelSettings`）から取得します。
  - その後は、メインエージェントが実行する各ターンから取得します。
  - すべての`/effort`の応答からも取得します。
  - ステータスラインがインストールされている場合は、Claude Codeがステータスラインに渡す情報からも取得します。確認は1秒ごとに行います。
- モデルを切り替えた場合は、ステータスラインが新しいモデルのレベルを報告するまで、それまでのレベルを維持します。報告には、そのモデルの上限やデフォルトも反映されます。

**スイッチ：`wf`と`uc`**

- `wf`は動的ワークフローのオンとオフを切り替えます（`workflows`設定）。使用中のClaude Codeにこの設定がある場合にだけ表示されます。
- `uc`は`/effort ultracode on`または`/effort ultracode off`を実行します。
  - Ultracodeにはワークフローが必要です。オフの場合は、`Ultracode needs Workflow turned on`というトーストが表示されます。
  - ワークフローをオフにすると、ultracodeもオフとして表示されます。
- スイッチはオフのときは灰色、オンのときはモデルの色の太字で表示されます。
- ターン中の`uc`のクリックは、推論レベルのクリックと同様に待機し、実行されるまで下線が付きます。その前にもう一度`uc`をクリックすると、取り消されます。

### ステータスライン（`hud/`）

claude-hud 0.8.0に、次の変更を加えています。

- **色で使用量を表示。** コンテキスト、5時間枠、7日間枠の使用量について、数値とバーに共通の配色を使います。使用量が少ないときは濃い緑で、増えるにつれて黄色を経て、上限に達すると赤になります。使用量が増えるほど明るくなるため、未使用に近いバーは控えめに、上限に近いバーは目立つように表示されます。この配色は、claude-hudの固定しきい値と、これらのバーに対する色の上書き設定を置き換えます。
- **バーで残量を表示。** `contextValue`または`usageValue`を`"remaining"`に設定すると（`hud/config.json`の設定例）、バーは残量に応じて埋まり、横の数値と一致します。残量が少しでもあれば、少なくとも1ブロックを表示します。
- **短いラベル。** `Context`、`Usage`、`Weekly`を、それぞれ`ctx`、`5h`、`7d`に変更します。`medium`は`med`と表示し、モデル名の括弧は省きます。
- **使用量の行のレイアウトを安定化。** 使用量の行ではリセット時刻の括弧を省きます。Claude Codeから5時間枠の情報が送られてこない場合は、`5h --`というプレースホルダーを表示し、レイアウトのずれを防ぎます。
- **コントロール行と推論レベルを共有。** コントロール行でクリックしたレベルがターン終了を待っている間も、そのレベルを表示します。また、Claude Codeから渡されたレベルをコントロール行に報告し、そちらにも表示できるようにします。

## インストール

### mod

Claude Codeのターミナルセッションのプロンプトで、次を実行します。

```
/plugin install hud-controls --marketplace imleben/claude-hud-controls
```

`y`と答えてマーケットプレイスを追加し、スコープを選びます（最初の選択肢はユーザースコープです）。コントロール行はそのセッションにすぐ表示され、ユーザースコープの場合は以降の新しいセッションにも表示されます。

シェルから実行する場合：

```sh
claude plugin install hud-controls --marketplace imleben/claude-hud-controls
```

`/plugin`を実行できないデスクトップアプリでは、プロンプト欄の横にある**+**をクリックし、**Plugins**、**Add marketplace**の順に選んで`imleben/claude-hud-controls`を追加し、**Add plugin**を選びます。

### ステータスライン

ステータスラインには、`PATH`上の[Bun](https://bun.sh)が必要です。代わりに、以下の`bun`をBunのフルパスに置き換えてもかまいません。このリポジトリをクローンします。

```sh
git clone https://github.com/imleben/claude-hud-controls.git ~/claude-hud-controls
```

`~/.claude/settings.json`に`statusLine`を設定します。`~/claude-hud-controls`以外にクローンした場合は、`plugin_dir=`の後のパスを変更してください。ラッパーがターミナルから幅を取得し、`refreshInterval`が5秒ごとにステータスラインを再実行するため、ターンとターンの間もコントロール行の状態が更新されます。

```json
{
  "statusLine": {
    "type": "command",
    "command": "bash -c 'cols=${COLUMNS:-}; case \"$cols\" in \"\"|*[!0-9]*) cols=$(stty size 2>/dev/null </dev/tty | awk '\"'\"'{print $2}'\"'\"');; esac; case \"$cols\" in \"\"|*[!0-9]*) cols=120;; esac; export COLUMNS=$(( cols > 4 ? cols - 4 : 1 )); plugin_dir=$HOME/claude-hud-controls/hud/; exec bun --env-file /dev/null \"${plugin_dir}src/index.ts\"'",
    "refreshInterval": 5
  }
}
```

上の画像と同じ表示にするには、`~/.claude/plugins/claude-hud/config.json`にまだ設定ファイルがない場合、`hud/config.json`をそこにコピーします。この設定では、推論レベル、ツール、エージェント、TODO、経過時間、設定数、セッション名を表示し、7日間枠を常に表示します。また、コンテキストと使用量は残量として表示します。

## 2つの部分で推論レベルを共有する仕組み

`~/.claude/hud-controls`内に、セッションごとに2つの小さなJSONファイルを作成して共有します。ファイルはローカルマシン上に保存され、プロンプトや会話記録の内容は含まれません。

| ファイル | 書き込み元 | 内容 |
| --- | --- | --- |
| `<session>.json` | ステータスライン（実行のたび） | Claude Codeから渡されたモデルIDと推論レベル、および実行開始時刻 |
| `<session>.pending.json` | コントロール行 | クリック後、ターン終了を待っているレベル、または`null` |

次の2つのルールにより、コントロール行に古いレベルが表示されるのを防ぎます。

- コントロール行は、現在動作中のモデルについての報告だけを使います。
- `/effort`の応答後は、その応答から1秒未満のうちに開始されたステータスラインの実行による報告を無視します。

新しいセッションでは、終了済みのセッションが残した待機中のレベルを消去します。ステータスラインは、このフォルダー内の7日を超えたファイルを削除します。ファイルに書き込めない場合でも、クリックした操作は1回実行されますが、ステータスラインへの表示だけが反映されません。

ステータスラインがなくても、コントロール行は設定、ターン、応答の情報に基づいて動作します。コントロール行がなくても、ステータスラインはClaude Codeが報告する情報を表示します。

## 確認

リポジトリのルートで実行します。

```sh
claude plugin validate .
claude plugin test .
```

テストでは、Claude Codeのモックに対してコントロール行を動作させ、次の項目を確認します。

- ターミナルとデスクトップでのクリックと色。
- ターン中のクリックと、最終的にどのクリックが実行されるか。
- 設定の拒否、確認の拒否、`auto`。
- プロンプトに入力した`/effort`。
- モデル切り替えを含むステータスラインの報告。
- ファイル書き込みの失敗、新しいセッション、再読み込み。

Claude Code 2.1.302でビルドとテストを行っています。
